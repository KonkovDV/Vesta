# Claims

If a sentence in `README.md` disagrees with this file or with [limitations.md](limitations.md), this file and the limitations win.

These rows are claims about this source tree. They are not a deployment report and not a model score.

| ID | Claim | Where it is checked |
| --- | --- | --- |
| C1 | One process listens. `src/index.ts` calls `runKernel()`. Importing the package does not listen. | `docs/architecture.md` |
| C2 | A product pins a 40-character commit. A branch name is not a pin. | [adr/0001-kernel-as-package.md](adr/0001-kernel-as-package.md). A git install of `e6814bb` from a local clone ran (MP-K5); an install from github.com has not been run. |
| C3 | This cut exports `ICronService` and `ICronJobRepository`. `runKernel()` does not start a cron timer and performs no one-shot wake-up; `overdueSlotDecision` is not in this tree. MP-K9. |
| C4 | A tool body that requires approval does not run unless the call has `approvalGranted`. The agent loop sets that flag after a recorded approval. A batch records `ask` and skips the body. The policy sees the validated arguments the body receives. | `src/application/agents/services/ToolRegistry.ts`, `src/application/agents/AgentRunService.ts`, `src/infrastructure/agents/BatchToolExecutorAdapter.ts`. `tests/unit/tool-registry.test.ts`. |
| C8 | One executor writes a run at a time. Every executor write carries the stream version it read; a cancel or a person's decision in between is skipped over, any other write means a second executor, and this one stops with `AgentRunConflictError` (or returns the result if that executor finished the run). So one tool call runs its body once, and a run has one model step per step and one `AgentRunFinished`. `ToolCallStarted` carries a lease (`toolLeaseMs`, default 15 min): while it lasts a resume elsewhere does not touch the run; after it the call is journaled as `outcome_unknown`, not run again. | `tests/unit/agent-run-service.test.ts`, `tests/integration/agent-run-postgres.test.ts`. |
| C9 | A kernel extension cannot replace or remove a registered token through the container it receives. Extension code runs in the same process with full privileges: it can still mutate an object it resolves. This is a guard against mistakes, not a sandbox. | `src/kernel.ts` (`createExtensionContainer`), `tests/unit/kernel-extensions.test.ts`. |
| C10 | A tool with external effects (exec, writes, messages, browser, sessions, automation) waits for a person by default; the decision is recorded with its author and the arguments hash, and the run resumes. An extension can add constraints, not remove them. | `tests/unit/tool-policy-service.test.ts`, `tests/unit/agent-run-routes.test.ts`. |
| C11 | `getCommittedEventsAfter` returns every committed event once, in commit order, including one whose transaction drew a lower gsn and committed later. When a committed event waits behind a transaction that is still open, the page names its timestamp in `heldSince`. The embedding worker reads only this way. | `tests/integration/event-commit-order.test.ts`, `tests/unit/semantic-embedding-worker.test.ts`. |
| C5 | The outbox hands each row to the bus at least once. A crash between the bus accept and the published mark leaves the row leased, then the worker tries again. A failed row waits for its backoff; versions of one aggregate leave in order. The default bus is Redis Streams (ADR-0004): the entry stays until a consumer group acknowledges it. A consumer that starts later still reads it. A read that is not acknowledged is delivered again. After the handler finishes, `processed_events` records the id so that consumer does not run it again. | `src/infrastructure/events/postgres-outbox.ts`, `tests/integration/outbox-delivery.test.ts`, `tests/integration/redis-streams-bus.test.ts`, `tests/unit/event-bus-transport.test.ts`. The kernel does not claim exactly-once across a network. On Redis older than 8.2, or one that refuses `INFO`, a group more than `EVENT_BUS_STREAM_MAXLEN` entries behind loses the oldest ones; from 8.2 a group more than `EVENT_BUS_STREAM_HARD_MAXLEN` behind does (MP-K52). An entry delivered `EVENT_BUS_STREAM_MAX_DELIVERIES` times without an acknowledgement, or one the bus cannot parse, goes to the dead-letter stream instead of its handler (MP-K50, MP-K51). `EVENT_BUS_TRANSPORT=pubsub` loses a message with no subscriber. |
| C6 | The kernel baseline is `001_consolidated.sql`. The next file, `002_runtime_tables.sql`, adds the seven `learning_*` tables, the three `error_graph_*` tables, and their HNSW indexes. `003_skill_graph_finops.sql` adds the four `skill_*` tables, their indexes, and `finops.agent_spend_state`. A database that already applied `001` and `002` accepts `003`. Replacing an applied file after its checksum was stored is still refused. A failed file does not store a checksum and stops the run. After migrate, the first use of every kernel store with DDL in its code sends no DDL command while `DB_RUNTIME_DDL` is unset: an event trigger on `ddl_command_start` records none. | `src/infrastructure/database/migrations/001_consolidated.sql`, `src/infrastructure/database/migrations/002_runtime_tables.sql`, `src/infrastructure/database/migrations/003_skill_graph_finops.sql`, `tests/integration/runtime-tables.test.ts`, `tests/unit/runtime-ddl.test.ts`; CI applies the directory twice on pgvector/PostgreSQL 17. |
| C12 | Sales, HR, healthcare, and ingest routes answer 403 unless the key has `sales.use`, `hr.use`, `healthcare.use`, or `memory.ingest`. MRI review and finalize also need `healthcare.review`.
